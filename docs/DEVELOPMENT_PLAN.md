# Cineo TV OS 开发计划

**基线：** 产品需求与技术架构 V1.0  
**计划状态：** 初始任务清单，待结合现有实现逐项复核<br>
**目标：** 交付可通过遥控器操作、连接自建 API，并在目标当贝设备播放授权视频资源的 Android TV MVP。

> 本仓库已存在核心页面、API 数据访问、SQLite 本地存储与 Media3 播放实现。下方清单保留初始验收基线，未勾选不等于没有代码；请结合 [当前状态](./README.md#当前状态) 核对。文中 Room / DataStore、分包结构等是计划目标，未全部落地。

## 1. 执行原则

- 按“工程基础 → Mock UI → API 联调 → Media3 播放 → 当贝真机验证”的顺序推进。
- 先采用单个 Android 应用模块和清晰的包结构；确认复杂度需要后再拆 Gradle 模块。
- UI 只依赖领域模型和 Repository，不在 Composable 中直接请求 API 或解析来源数据。
- 每个可操作界面都要能用 D-pad 完成导航；遥控器焦点恢复属于功能验收内容。
- API 协议和真实设备能力以实际确认结果为准，不把建议接口或模拟器表现当成已验证事实。
- 客户端只播放后端提供且有权访问的资源，不实现站点爬取、DRM 绕过或媒体访问控制规避。

## 2. MVP 范围

### 必须交付（P0）

- Android TV 启动入口、页面导航和可折叠侧栏。
- 首页推荐/继续观看/最近更新等内容区域（具体分组由后端数据决定）。
- 分类列表、关键词搜索、影视详情、电视剧季/集选择。
- 可配置 API 地址，并能验证服务器连通性。
- Media3 播放 MP4 和 HLS/M3U8，支持暂停、继续、进度跳转及手动线路切换。
- 本地观看记录和断点续播。
- 全流程遥控器操作、加载/空/错误状态和明确的返回路径。
- 在 Android TV 模拟器及目标当贝设备完成安装和核心流程验证。

### MVP 后（不阻塞首版）

- **P1：** 收藏、字幕/音轨选择、自动下一集、线路失败容错、跨设备历史与收藏同步。
- **P2：** 手机二维码配置、多用户账户、DLNA/投屏。

## 3. 阶段路线

```text
阶段 0 基础条件与工程
          ↓
阶段 1 TV 导航和设计系统
          ↓
阶段 2 Mock 数据核心页面
          ↓
阶段 3 API 与本地数据接入
          ↓
阶段 4 Media3 播放闭环
          ↓
阶段 5 当贝验证与 MVP 发布
```

API 合同、设备型号等确认工作可以与不依赖它们的 Mock UI 开发并行；真实 API 联调和目标设备验收必须等待相应信息可用。

## 4. 任务清单

状态标记：`[ ]` 未开始，`[/]` 进行中，`[x]` 完成，`[-]` 暂缓。任务按先后依赖排列，不代表日历工期。

### 阶段 0 — 基础条件与工程

**交付：** 工程可构建并在 Android TV 模拟器启动；关键外部依赖已登记。

- [ ] **FND-01** 确认 Android Studio、Android SDK、Gradle/JDK 可用；记录模拟器目标 API Level。
- [ ] **FND-02** 确认当贝型号、系统版本/API Level、安装与 ADB 调试方式。关联 [D-01](./DECISIONS.md#d-01-目标当贝设备)。
- [ ] **FND-03** 初始化 Kotlin Android TV 工程、应用 ID、版本配置、TV Launcher 声明和 Compose for TV 基础依赖。
- [ ] **FND-04** 建立包结构：`app`、`core/model`、`core/network`、`core/datastore`、`core/designsystem`、`core/player`、`data`、`feature/*`。
- [ ] **FND-05** 配置版本目录和基础构建选项；确定最低/目标 SDK，避免在设备范围未确认时随意锁定。
- [ ] **FND-06** 建立启动、返回和错误兜底路径；添加用于 UI 开发的 Mock Repository。
- [ ] **FND-07** 记录构建、模拟器运行、安装和日志查看步骤，确保工程可由其他开发者复现。

**阶段验收：** 应用能构建、出现在 TV Launcher 并启动；方向键可操作基本导航；Mock 数据可注入页面；项目 SDK 和目标设备假设有记录。

### 阶段 1 — TV 导航与设计系统

**交付：** 可复用的 TV 视觉与焦点交互基础。

- [ ] **UI-01** 定义深色主题、颜色、字体、间距、海报比例和焦点动效。
- [ ] **UI-02** 实现 `TvSidebar`：展开/收起、当前项、D-pad 上下切换和统一返回规则。
- [ ] **UI-03** 实现可复用焦点按钮、海报卡片、横向内容行和 Hero 背景组件。
- [ ] **UI-04** 确认首次启动和未配置服务端时的导航入口。
- [ ] **UI-05** 在 TV 模拟器检查安全边距、焦点高亮、文本可读性及横向列表焦点移动。

**阶段验收：** 侧栏和公共控件可由遥控器完整操作；焦点清晰且不会因收起/展开或列表滚动而丢失。

### 阶段 2 — Mock 数据核心页面

**交付：** 不依赖真实后端即可演示核心浏览路径。

- [ ] **FEAT-01** 实现首页：Hero、继续观看、最近更新及推荐内容行。
- [ ] **FEAT-02** 实现分类页与分页/加载更多的界面状态。
- [ ] **FEAT-03** 实现搜索输入、提交、结果列表和无结果状态。
- [ ] **FEAT-04** 实现详情页：海报/背景、元信息、简介、播放入口、线路入口、收藏入口。
- [ ] **FEAT-05** 为电视剧详情实现季、集选择；电影隐藏不适用的选集区域。
- [ ] **FEAT-06** 实现页面间导航、返回和返回后焦点/滚动位置恢复。
- [ ] **FEAT-07** 为核心页面补齐加载、空数据、网络失败占位状态（Mock 阶段可先演示状态）。

**阶段验收：** 使用 Mock 数据完成“首页 → 搜索或分类 → 详情 → 选集”的全遥控器浏览流程；主要页面有加载、空和错误状态设计。

### 阶段 3 — 服务端配置、API 与本地数据

**前置条件：** [D-02](./DECISIONS.md#d-02-服务端-api-协议) 的 API 地址、认证和响应协议已确认；可访问测试环境或约定 Mock API。

**交付：** 浏览、搜索、详情和集数由真实 API 驱动；服务器配置可保存和验证。

- [ ] **DATA-01** 确认并记录真实 API 契约：基础 URL、健康检查、分页、错误结构、鉴权、超时及兼容版本。
- [ ] **DATA-02** 定义领域模型及 API DTO，明确字段映射、可空字段和未知字段处理。
- [ ] **DATA-03** 实现 Retrofit/OkHttp、序列化、统一错误映射和请求日志脱敏。
- [ ] **DATA-04** 实现服务器地址设置、输入校验、连通性检查和持久化；失败时保留重新设置入口。
- [ ] **DATA-05** 接入首页、分类、内容列表和搜索 API。
- [ ] **DATA-06** 接入详情、季/集和播放线路查询 API。
- [ ] **DATA-07** 使用 Room 保存观看历史/进度；使用 DataStore 保存服务器地址和轻量偏好。
- [ ] **DATA-08** 统一 UI 的加载、空结果、超时、服务端错误和重试行为。

**阶段验收：** 配置有效服务端后可完成“首页 → 搜索/分类 → 详情 → 指定集”；服务端不可用或数据为空时界面有可理解的反馈；本地配置重启后仍存在。

### 阶段 4 — Media3 播放闭环

**前置条件：** [D-03](./DECISIONS.md#d-03-内容授权与测试资源) 确认授权测试资源；播放解析接口及 URL/Headers/过期规则明确。

**交付：** 播放 MP4 与 HLS 的核心操作、线路切换和断点续播可用。

- [ ] **PLAY-01** 通过 Media3 建立单一播放器会话管理，处理 Activity/页面生命周期和资源释放。
- [ ] **PLAY-02** 对接播放线路列表与播放解析接口，构造 MediaItem 并处理必要请求头和过期信息。
- [ ] **PLAY-03** 实现全屏播放器界面、播放/暂停、当前位置/总时长、Seek、缓冲和错误提示。
- [ ] **PLAY-04** 实现 D-pad 播放控制、控制层显示/隐藏、返回详情和选集入口。
- [ ] **PLAY-05** 实现手动切换线路；切换后在新资源可用范围内恢复播放位置。
- [ ] **PLAY-06** 定时及退出时保存播放进度；详情页提供继续播放；进度完成后按产品规则清理或标记完成。
- [ ] **PLAY-07** 区分网络、解析、格式/解码及资源失效错误，提供重试或回选线路。
- [ ] **PLAY-08** 检查重复进入/退出、页面重建、暂停恢复时播放器未重复创建且能释放解码资源。

**阶段验收：** 使用授权 MP4 与 HLS 测试资源完成播放、暂停、Seek、切线路、退出及恢复进度；播放失败有明确反馈；遥控器全流程可用。

### 阶段 5 — 当贝验证与 MVP 交付

**前置条件：** 目标设备信息已确认且设备可用于安装测试。

**交付：** 可安装的 MVP APK 和目标设备验证记录。

- [ ] **REL-01** 在 Android TV 模拟器按验收清单走查首页、搜索、详情、选集、播放、设置和返回。
- [ ] **REL-02** 在当贝设备验证安装、TV Launcher 启动、D-pad 键值、音视频解码、休眠唤醒和应用恢复。
- [ ] **REL-03** 验证目标分辨率下的焦点、字体、安全边距、海报加载和滚动表现。
- [ ] **REL-04** 验证弱网、断网、超时、API 不可用、播放地址过期和线路失败恢复。
- [ ] **REL-05** 处理设备验证中发现的兼容性与性能问题，确认播放器离开后资源释放。
- [ ] **REL-06** 产出带版本号的 APK、构建/安装说明和已知问题记录。

**阶段验收：** 完成需求文档第十二节的 MVP 验收项；模拟器与当贝测试结果分别记录；发布 APK 可安装启动且核心流程通过。

## 5. MVP 完成检查

- [ ] Android TV 模拟器安装、启动和 Launcher 展示正常。
- [ ] 目标当贝设备安装、启动和基础兼容性验证完成。
- [ ] 所有核心流程不依赖鼠标或触屏，可仅用遥控器完成。
- [ ] 首页、搜索、详情和电视剧选集接入 API。
- [ ] MP4 和 HLS/M3U8 可播放，播放控制和手动换线可用。
- [ ] 本地播放进度能保存并恢复。
- [ ] 可配置自建 API 地址，错误状态明确。
- [ ] 反复进入和退出播放器后没有持续占用解码资源的问题。
- [ ] APK、安装说明和设备验证记录已归档。

## 6. 主要风险与依赖

| 项目 | 影响 | 跟进方式 |
|---|---|---|
| 当贝型号/API Level 不明 | SDK 最低版本、键值、解码和安装兼容性无法最终确定 | 跟进 [D-01](./DECISIONS.md#d-01-目标当贝设备) |
| 真实 API 尚未提供或协议未知 | 无法完成阶段 3 的真实联调 | 跟进 [D-02](./DECISIONS.md#d-02-服务端-api-协议)；阶段 2 可使用 Mock 推进 |
| 授权播放资源与可复现测试地址未知 | 播放和线路切换验收不可复现 | 跟进 [D-03](./DECISIONS.md#d-03-内容授权与测试资源) |
| Android TV / Compose TV 依赖版本及设备最低 API 未核实 | 构建配置可能需要调整 | 阶段 0 基于实际 SDK/目标设备确认并记录 |
| 播放 URL 生命周期、请求头和认证规则未知 | 线路切换、重解析和错误恢复设计不完整 | 在阶段 3 API 契约评审中明确 |

## 7. 每项任务的完成标准

任务完成时应满足：

1. 对应功能可从用户路径进入并具备明确的返回行为。
2. 遥控器可完成该功能的主要操作，焦点状态清楚。
3. 加载、空内容和失败状态按该任务范围处理。
4. 不把令牌、敏感请求头或完整授权播放地址写入日志。
5. 文档中的任务状态和相关决策状态已同步更新。
